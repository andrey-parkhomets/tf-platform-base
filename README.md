# Terraform Platform Base

A small Terraform repository for a data platform on Azure: networking, storage, secrets, monitoring, data integration, analytics and a function app.

## Layout

```text
modules/            Reusable modules. Each has main.tf, variables.tf, outputs.tf and versions.tf.
  <module>/tests/   Tests for a module, where they exist. Run them from the module folder.
stacks/
  data-platform/    The stack that uses the modules. One set of variables per environment in envs/.
```

## Requirements

- Terraform 1.9 or newer
- Internet access to download providers
- No Azure subscription or credentials

## Run the tests of a module

The tests use a mocked `azurerm` provider, so they need no credentials.

```sh
cd modules/storage-account
terraform init -backend=false
terraform test
```

## Check the stack

```sh
cd stacks/data-platform
terraform init -backend=false
terraform fmt -check -recursive ../..
terraform validate
```

The stack has no backend configured. A real deployment would need one, and credentials for it.

## Local tooling

```sh
brew install pre-commit tflint   # or your package manager
pre-commit install                               # fmt, validate, tflint, basic file checks
```

Module READMEs between `BEGIN_TF_DOCS` and `END_TF_DOCS` are generated by `terraform-docs`; do not edit them by hand.
CI fails a pull request whose README is out of date. CI uses the `terraform-docs` that is bundled in the
`terraform-docs/gh-actions` image (v0.20.0 today), and newer versions format tables differently, so refresh READMEs with that
same binary instead of a locally installed one:

```sh
docker run --rm -v "$PWD":/ws -w /ws --entrypoint terraform-docs quay.io/terraform-docs/gh-actions:1.4.1 \
  --config .terraform-docs.yml --output-mode inject --output-file README.md modules/<name>
```

## Pull request automation

Every pull request that changes a module or stack gets lint, Checkov and the existing tests, and one comment that lists
modules without tests. The agent that writes tests runs only when someone asks, with a comment on the pull request:
`agent coverage`, `agent check comments` or `agent remove <sha>`. Verified tests are committed to the branch.
See [SOLUTION.md](SOLUTION.md). Fast local tests of the safety scripts (no Docker, no network):

```sh
scripts/test-guards.sh
```

## Conventions

- Resource files in a stack and modules use `main.tf`, `variables.tf`, `outputs.tf` and `versions.tf`.
- Use `for_each` rather than `count` for repeated resources.
- Environments are `dev`, `uat` and `prod`.
- Format code with `terraform fmt -recursive` before committing.
